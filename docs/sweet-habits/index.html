🍓 Sweet Habits

A habit-tracking concept exploring how routine-building can feel calm, encouraging, and easy to return to without hiding useful progress information.

Try Live PrototypeGitHub Case StudyFigma

Design challenge

Habit tools often balance speed versus customization, accountability versus pressure, and data richness versus visual calm. Sweet Habits explores a smaller core flow with supportive feedback.

Research status

Honest status: research questions and usability plans are documented, but participant findings are not claimed yet.

Questions focus on setup friction, reminder expectations, feedback tone, progress visibility, and whether motion/mascot feedback communicates system status clearly.

User flow

Primary: Home → Add Habit → Configure → Save → Complete → Feedback → Progress.

Secondary: edit/pause · missed-day recovery · reminder settings · weekly progress · reduced-motion preference.

Wireframe strategy

The documented process calls for multiple low-fidelity approaches before visual polish. The remaining portfolio evidence is to show those alternatives and explain why the selected hierarchy won.

Visual system

Blush pink, lavender, mint and cream support a warm tone. Rounded controls, calm density, visible status, and short transitions reinforce the product principles.

Working coded prototype

The live prototype implements onboarding, habit creation, frequency/reminder setup, completion/uncompletion, weekly progress, habit detail/editing, pause/resume, missed-day recovery, settings, reduced motion, form validation, and loading/error/empty/success states.

Accessibility approach

Keyboard-operable controls, labels, focus management, non-color status, reduced-motion behavior, semantic structure, and responsive layouts are built into the prototype. Formal certification is not claimed.

Testing & iteration

Planned tasks include adding a habit, setting a reminder, completing a habit, finding weekly progress, and editing an existing habit. Final iteration stories should connect actual observations to specific design changes once testing occurs.

Handoff

Documentation covers states, responsive assumptions, motion behavior, accessibility intent, and developer-oriented implementation details.

Next evidence to add

  • Interview and usability findings from real participants
  • Low-fidelity alternatives and selection rationale
  • Before → evidence → after iteration examples
  • Formal accessibility review and deeper Figma exports
